1   Introduction

    The primary objective of the R-Type project is to create a multiplayer game supporting up to four players.

3.  R-Type architecture

    The R-Type architecture adopts a client-server model.
    Clients establish an initial connection with the server using the
    defined protocol and subsequently spawn within the game environment.

4. Protocol

    The entire communication link between the server and the client hinges on the utilization
    of a UDP protocol for sharing payloads. The game opts for the UDP Protocol over the TCP
    Protocol, considering its better alignment with our specific requirements. While TCP is
    renowned for its reliability, it tends to transfer data at a slower pace. In contrast, UDP,
    although less reliable, operates more swiftly.

        4.1. Contents Of Payload

            In order to communicate between the client and the server,
            these MUST be the contents of a payload:

            Std::string Data;

            The data string is encrypted when sent and decrypted when received using a unique
            key that the server and client have in common.
            From now on, every time this document mentions "data", it will refer to the PACKET_TYPE


        4.2. Connection To Server

            When launching the game, the client MAY enter his login
            information. The client MAY provide an IP and a
            Port so as to connect to the server.
            If the client doesn't provide these informations, he MUST
            automatically be given these login informations:

                UUID = 127.0.0.1:8080
                IP = 127.0.0.1
                Port = 8080

            This prompts the client to dispatch a payload to the server,
            comprising:

                Data : "New Connection"*

            This causes the client to automatically join a room. For more
            information, please refer to 4.3. Connection To Room.Th

            With "UUID" being the UUID of each player in the room
            and "readyState" being the status of each player in the room
            (ready or not ready).

            On failure, no message is sent between the client and the
            server.


        4.3. Connection To Room

            Upon establishing a connection between the client and the server, the client will be
            promptly allocated to a room. If no available rooms are found or all existing rooms
            reach full capacity, a new room will be generated. Consequently, the client seamlessly
            joins the first available non-full room identified by the server, or a new room is imperative
            if none exists.
            To exit a room, the client is required to transmit to the server the following data: DISCONNECTION.


        4.4. Start The Game

            Upon a client's successful entry into a room, the prerequisite for
            commencing the game is that every participant within that room must
            indicate readiness. To fulfill this requirement, each client is obliged
            to transmit the following data to the server:
                "READY"
            Once the readiness of all players is confirmed, the server is mandated to
            broadcast to all clients within the room:
                "START"
            Subsequently, when all players in a room have met their demise, the server
            is compelled to dispatch the following data to the client:
                "END_GAME"


        4.5. In game Communication

           Throughout gameplay, the client is restricted to a limited set of inputs,
           encompassing actions such as movement, shooting, and exiting. To transmit
           this information to the server, the client is required to dispatch the following:
                Data = MOVE
                Data = Direction
            The client must specify a direction for movement (UP, DOWN, LEFT, RIGHT).
            If the client intends to initiate shooting, the obligatory transmission to the server is:
                Data = SHOOT
            Similarly, when the client decides to exit the game, the mandatory communication to the server is:
                Data = DISCONNECTION
